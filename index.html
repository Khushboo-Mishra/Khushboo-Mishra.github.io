    Creator Matchmaker

    Top two, NYU SPS x Google hackathon
    YouTube creator selection for marketing campaigns

    Takes a campaign brief and returns a four-creator roster with a plain-language report. It finds candidates on YouTube, screens them on measurable activity and engagement, has Gemini evaluate the evidence, and ranks the shortlist on six dimensions. Every run saves an audit file, so weights can be changed and creators swapped later without new API calls. Missing evidence stays empty instead of being guessed, and an API failure stops the run instead of filling in fake scores.

    1. Campaign brief
    2. YouTube discovery
    3. Screening
    4. Evidence evaluation
    5. Six-dimension ranking
    6. Four-creator roster
    7. Report and audit file

    The blue step uses Gemini. Demo mode runs the whole backend on clearly labeled synthetic data with no API keys. The repo has 154 test functions.

    AgentOps

    Winner, Apexon x NYU hackathon
    Incident response for production systems

    A 13-stage agent pipeline that takes a production signal through reasoning, a confidence score, risk and policy gates, human approval and audit logging. It ships with four incident scenarios, and each one can land in a different decision zone. With no model installed it falls back to a deterministic simulation, so it always runs.

    Credit risk agent

    Winner, NYU x NextAML hackathon
    Commercial loan underwriting

    A digital credit committee. Seven agents read a loan application PDF, compute leverage and coverage, score expected loss, check lending policy and write the credit memo. The numbers come from deterministic credit models. The language model only handles industry risk and the written explanation, and it runs locally.

    1. Document processing
    2. Financial analysis
    3. Risk scoring (PD x LGD)
    4. Industry risk
    5. Policy compliance
    6. Credit decision
    7. Credit memo

    Blue steps use the LLM. The rest are deterministic. Decisions are approve, approve with conditions, or decline.

    • FastAPI
    • Streamlit
    • SQLAlchemy
    • Llama 3 via Ollama

    SQL-MCP-101

    Open source teaching project
    A governed MCP server, written to be read

    The idea: do not hand a model your database schema, give it business entities. The server exposes questions like course catalogue or headcount per department. There is no run_query tool, so a caller cannot express a statement the server did not design. It also demonstrates all three MCP primitives and who controls each.
